Configuration cheat sheet

SettingShort note
durationHow long bursts continue.
rateBursts started per second.
burst_sizeVirtual users prepared for each burst.

Concurrency formula

weighted:    max_inflight >= burst_size
coordinated: max_inflight >= burst_size x scenario count
Example: 100 users x 3 coordinated scenarios needs at least 300 in-flight slots.

Request body and data

Body template

Change body_file when APIs need different JSON structures.

Dataset overlay

Set overlay_dataset_keys to true to replace matching template fields.

Shared dataset

Use shared_dataset_file so coordinated scenarios receive the same entity.

Dataset keys not present in the body template are ignored.

Tokens

First Scenario environment variable Fallback Scenario token file

New-Item -ItemType Directory -Path .\secrets -Force
Set-Content .\secrets\api-a.token "<API-A-JWT>"
Set-Content .\secrets\api-b.token "<API-B-JWT>"

Optional environment override:

$env:API_A_TOKEN = "<API-A-JWT>"
$env:API_B_TOKEN = "<API-B-JWT>"
"token_env": "API_A_TOKEN",
"token_file": "../../secrets/api-a.token"
Never save JWT values directly in shared JSON configs, logs, or documentation.

Run

Safe first run

.\loadtest.exe `
  -config .\configs\examples\100-users-one-record.json `
  -log-request-body=false `
  -log-response-body=false
Request and response body logging is off, but response files are still created.

Disable response files only when required

.\loadtest.exe -config .\configs\patient-import.json -response-dir ""

Responses

Each run creates responses\responses_YYYYMMDD-HHMMSS.json.

Get-ChildItem .\responses\*.json |
  Sort-Object LastWriteTime -Descending |
  Select-Object -First 1
summary.completed

Requests that finished.

summary.failed

Unexpected statuses and network failures.

dropped_arrivals

Requests skipped because concurrency was full.

duration_ms

Compare slow scenarios and lock waits.

status / error

Check timeouts, conflicts, and server errors.

body

Check API-level success and returned entity data.

Fast troubleshooting

  • 403: check token, proxy, VPN, WAF, and IP policy.
  • 401: refresh the JWT and verify the scenario token source.
  • Dropped arrivals: increase max_inflight or reduce burst size.
  • Body errors: verify JSON, placeholders, dataset fields, and file paths.
  • Slow responses: inspect P95/P99, DB locks, connection pools, and server CPU.
  • No response file: check -response-dir and application errors.
  • Wrong scenario ratio: weighted results are approximate in short tests.

Before every test

  • Approved environment and load level.
  • Correct URL, method, body, dataset, and expected statuses.
  • Valid per-scenario token.
  • Correct execution and shared dataset mode.
  • Enough in-flight capacity for the burst.
  • API and database monitoring enabled.
  • Plan to protect or delete response files containing sensitive data.
